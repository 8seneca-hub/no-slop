# slop-code (NS-K)

Judge a comment by one test: would a competent reader lose information if it vanished? If not, it is slop. Tiers: see `no-slop`. Scope guard: change comments only. Never touch code, identifiers, imports, whitespace or formatting. When unsure whether a line is code or comment, leave it.

## Remove

| Id | Tier | Pattern | Why |
|---|---|---|---|
| NS-K-01 | Q | Restates the next line: `// increment counter` over `count++` | Doubles the reading, adds nothing |
| NS-K-02 | Q | Narrates steps: `// Step 1: validate`, `// First... Next...` | Flow is visible in the code |
| NS-K-03 | P | Announces the edit: `// Added function to...`, `// Updated to fix`, `// New code` | History belongs in git, and the comment rots on the next change |
| NS-K-04 | Q | Boilerplate header: `Generated by`, `This file contains`, author and date banners, license repeated per file | Noise at the top of every file |
| NS-K-05 | Q | Section dividers and banners: `// ------ ROUTES ------`, ALL CAPS labels | Decoration, no content |
| NS-K-06 | P | To-do note with no owner, no task, no link: `// TODO: improve` | Nobody can act on it |
| NS-K-07 | P | Commented-out code | Git remembers it. Delete it |
| NS-K-08 | Q | Signature echo: `@param name The name.` | Repeats the declaration |
| NS-K-09 | Q | Empty labels: `// Main logic`, `// Helper`, `// Important!` | A category, not a fact |
| NS-K-10 | Q | Emoji or cheer in comments | Decoration |
| NS-K-11 | P | Comment that contradicts the code | Wrong is worse than absent. Fix the comment, or flag it if the code is the suspect |

## Keep

- Why something is done: the constraint, the trade-off, the bug it avoids.
- Units, ranges, invariants, ordering and locking rules: `// ms, not seconds`.
- Links to a spec, ticket or incident that explains the code.
- Warnings: `// do not reorder: the second call reads the first's cache`.
- Public API docs that state behaviour, errors or side effects.
- TODOs with an owner and a task: `// TODO(minh, #212): drop after the v2 import ships`.
- License headers the project requires.

## Commit messages and PR text (NS-K-12 to NS-K-15)

| Id | Tier | Rule |
|---|---|---|
| NS-K-12 | Q | Subject in the imperative, under about 72 characters, says what changed and where. |
| NS-K-13 | P | The body gives the reason and anything the diff cannot show: risk, trade-off, how it was verified. It does not list files or repeat the diff. |
| NS-K-14 | Q | No "This PR", "This commit", "I have", "In this change we". Start with the change. |
| NS-K-15 | H | No claim that was not run: "all tests pass" needs a run behind it. No invented ticket numbers. |

## Before and after

```ts
// Before
// ============ Retry helper ============
// Added function to retry the request
// Step 1: loop up to 3 times
for (let i = 0; i < 3; i++) {
  // Try to send the request
  const res = await send(req);
  // TODO: improve this
  // if (res.status === 429) await sleep(1000);
  if (res.ok) return res;
}
```

```ts
// After
// The upstream drops one in about fifty calls; three tries kept errors under the SLO (INC-418).
for (let i = 0; i < 3; i++) {
  const res = await send(req);
  if (res.ok) return res;
}
```

Commit, before: `Updated the retry logic. This PR adds a retry helper that retries the request up to three times and updates the tests.`
Commit, after: `Retry upstream sends up to 3 times` with a body: `The upstream drops about 2% of calls. Checked with 1,000 calls against staging: 0 failures after the change.` (Use real figures from a real run. Do not copy these.)

## Process

1. Read the file. List comments by line.
2. Mark each one Remove, Keep or Fix (NS-K-11).
3. Edit comments only. Run the project's formatter check or tests if they exist, to prove the code did not change.
4. Report: count removed, count kept, any conflict with repo comment rules (the repo wins).

Linter: `node scripts/slop-lint.mjs --scope code-comment <files>` catches the mechanical cases (NS-K-03, 04, 05, 06). Judgment covers the rest.
